# SagePlan (unofficial)

An unofficial, browser-local web app that tells a Pomona College student which
graduation and general-education requirements they have satisfied, which
remain, and which specific courses, actually offered in an upcoming term, would
close the gaps. Everything the student enters stays in their browser.

**The Registrar's official audit is the source of truth. Confirm with your
advisor before registering.**

This repository is run by a fleet of specialised Claude Code agents under the
protocol in `docs/AGENT_PROTOCOL.md`. Humans: start with `docs/PRODUCT.md`.

---

## What is here

| Path | What |
|---|---|
| `docs/PRODUCT.md` | problem, users, P0 scope, demo flow, roadmap |
| `docs/ARCHITECTURE.md` | static SPA + nightly pipeline; no server, no database; model assignment |
| `docs/DESIGN_BRIEF.md` | the design problem: one page, margin of evidence, term ribbon |
| `docs/API.md` + `docs/openapi.yaml` | the data and engine contract (openapi is generated from `packages/shared`) |
| `docs/DATABASE.md` | browser persistence: localStorage, export file, share-link fragment |
| `docs/ACCEPTANCE.md` | what done means, criteria by ID, engine fixtures |
| `docs/DECISIONS.md` | ADRs |
| `docs/tasks/` | one file per task; `INDEX.md` is generated by `scripts/tasks.sh` |
| `packages/shared` | **the contract**: zod schemas and types. Owner: manager |
| `packages/engine` | pure requirement evaluator (frontend builds it) |
| `packages/pipeline` | nightly ingestion scripts (backend builds it) |
| `apps/web` | the single-page React app (frontend builds it) |
| `data/programs/general-education-2026.json` | GE requirements as data, every rule with its verbatim catalog quote |
| `data/external-credit-rules.json` | AP / IB / A-Level / SAT-II thresholds |
| `data/sources/` | committed inputs: Registrar GE export, catalog page snapshots |
| `data/*.json` (generated) | catalog, sections, offering history, manifest, written by the pipeline |

## Quick start

```bash
scripts/bootstrap.sh          # installs, writes .env with your port
source .env
npm run dev                   # apps/web on FRONTEND_PORT
npm test                      # every workspace
scripts/contract-test.sh      # contract current, data valid (exit 2 = pipeline not run yet)
```

Pipeline (build time only; the browser never calls these APIs):

```bash
npm run pipeline:all          # catalog -> sections -> history -> validate -> manifest
```

## Data sources and attribution

- Course catalog: Pomona College Catalog 2026-27 via Coursedog. Policy text is
  quoted verbatim beside every requirement and snapshotted in
  `data/sources/catalog-pages/`.
- Sections and offering history: [Hyperschedule](https://hyperschedule.io)
  (BSD-3-Clause). Redistributed with attribution; the Hyperschedule
  contributors do not endorse this project. Fetched nightly in CI, never from a
  user's browser.
- Cross-check: a Registrar GE course export (course-level data only; no student
  data), committed at `data/sources/`.

## Privacy

No server, no accounts, no analytics. The student's plan lives in
`localStorage`, in files they export, and in share links whose payload is in
the URL fragment (never sent to any host). The page ships a
Content-Security-Policy with `connect-src 'self'` so an accidental request
fails loudly.

## Maintenance and succession

This tool is maintained by its owner, a Pomona student, through graduation.
Every unofficial student tool dies the same way: the author graduates, the
catalog changes, and the site keeps confidently showing last year's rules. So:

- The UI shows the catalog year and "data as of" on every page load, and a
  staleness banner appears automatically when the data is older than one
  catalog year.
- **Successor:** to be named before public launch. Until a successor, an owning
  campus organisation, or a sunset date is written here, the app is not to be
  publicly advertised. (Owner: fill this in; the reviewer checks it at launch.)
- Adding a major or minor is a JSON file in `data/programs/` with verbatim
  catalog quotes, validated by `scripts/contract-test.sh`. No code changes.

Before public launch: courtesy note to the Registrar; email to the
Hyperschedule maintainers; re-verify the status of the College's Anthology
degree-audit project.

## Agents

Baseline branches `main` (manager), `agent/frontend`, `agent/backend`,
`agent/reviewer`. `scripts/launch-agents.sh` prints the terminal commands;
`scripts/status.sh` shows every branch and its current task. The protocol is
`docs/AGENT_PROTOCOL.md`; the visual constraints are `docs/DESIGN_CONSTRAINTS.md`
(the only copy).
